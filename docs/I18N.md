# GearUI I18n System

[English](./I18N.md) | [简体中文](./I18N.zh-Hans.md)

One language runtime serves every layer. GearUI Kit does not centrally host
other libraries' text: each library defines its own typed strings and shares
the language environment GearUI provides. Applications declare the language
once — `App(languageTag = ...)` — and every pack recomposes on a switch.

## 1. Architecture

```text
App (languageTag, fallbackLanguageTag, stringsOverrides)
  └── I18nRoot                                    ← provided by gearui-kit
        ├── LocalLanguageTag         (BCP47, normalized)
        └── LocalFallbackLanguageTag (BCP47, normalized)
              ├── I18nProvider (LocalStrings)               ← gearui-kit's own pack
              ├── PrivChatUiI18nProvider (LocalPrivChatUiStrings) ← upper library mounts its own
              ├── ... any further layer
              └── content
```

Every provider:

- reads `LocalLanguageTag.current` / `LocalFallbackLanguageTag.current`;
- resolves its base pack from its own builtin map (`resolveLanguagePack`);
- applies caller-supplied `Map<String, XxxPatch>` field-level overrides;
- caches the immutable result with `remember(tag, fallback, overrides)`;
- exposes it through a `staticCompositionLocalOf` to same-library components.

Type safety + field-level overrides + a single language switch point + zero
boilerplate in the application layer.

## 2. Integration Steps (upper libraries)

Business applications skip this section — `App(languageTag = ...)` is enough.

### 2.1 Strings model and patch

```kotlin
@Immutable
data class PrivChatUiStrings(
    val messageDeleted: String,
    val chatTyping: String,
)

@Immutable
data class PrivChatUiStringsPatch(
    val messageDeleted: String? = null,
    val chatTyping: String? = null,
)

val PrivChatUiStringsPatch.isEmpty: Boolean
    get() = messageDeleted == null && chatTyping == null

fun PrivChatUiStrings.merge(patch: PrivChatUiStringsPatch?): PrivChatUiStrings {
    if (patch == null || patch.isEmpty) return this
    return copy(
        messageDeleted = patch.messageDeleted ?: messageDeleted,
        chatTyping = patch.chatTyping ?: chatTyping,
    )
}
```

### 2.2 Builtin packs

```kotlin
object PrivChatUiStringPacks {
    val English: PrivChatUiStrings = PrivChatUiStringsEnUs
    val ChineseSimplified: PrivChatUiStrings = PrivChatUiStringsZhHans

    val builtIn: Map<String, PrivChatUiStrings> = mapOf(
        "en-US" to English, "en" to English,
        "zh-Hans" to ChineseSimplified, "zh-CN" to ChineseSimplified,
        "zh" to ChineseSimplified,
    )
}
```

### 2.3 Provider and accessor (core)

```kotlin
val LocalPrivChatUiStrings = staticCompositionLocalOf { PrivChatUiStringPacks.English }

@Composable
fun PrivChatUiI18nProvider(
    overrides: Map<String, PrivChatUiStringsPatch> = emptyMap(),
    content: @Composable () -> Unit,
) {
    val tag = LocalLanguageTag.current          // from App / I18nRoot
    val fallback = LocalFallbackLanguageTag.current
    val strings = remember(tag, fallback, overrides) {
        resolveLanguagePack(tag, PrivChatUiStringPacks.builtIn, fallback)
            .merge(resolvePatch(tag, fallback, overrides))
    }
    CompositionLocalProvider(LocalPrivChatUiStrings provides strings, content = content)
}

object PrivChatUiI18n {
    val strings: PrivChatUiStrings
        @Composable get() = LocalPrivChatUiStrings.current
}
```

`resolvePatch` normalizes override keys and walks the tag's subtag chain
(`zh-Hans-CN → zh-Hans → zh`), ending at the fallback tag.

### 2.4 Application mount

```kotlin
App(
    languageTag = lang,
    stringsOverrides = mapOf(             // optional: override GearUI builtin text
        "zh-Hans" to StringsPatch(common = CommonStringsPatch(confirm = "确定一下")),
    ),
) {
    PrivChatUiI18nProvider(               // optional: override the library pack
        overrides = mapOf("zh-Hans" to PrivChatUiStringsPatch(messageDeleted = "这条消息已撤回")),
    ) {
        AppContent()
    }
}
```

## 3. Semantic Domain Splitting (mandatory)

A single `Strings` data class that grows to dozens of fields pushes Kotlin's
generated `copy` / `equals` / `hashCode` / `componentN` toward the DEX method
and 255-parameter limits — on Android this surfaces as a runtime `VerifyError`
the moment one key is added, and only on Android. Text is therefore split into
small per-domain data classes:

```kotlin
// gearui-kit domains: common / theming / field / dateTime / feedback / media / guide
@Immutable
data class Strings(
    val common: CommonStrings,
    val theming: ThemeStrings,
    // ...
)

data class StringsPatch(
    val common: CommonStringsPatch? = null,
    val theming: ThemeStringsPatch? = null,
    // ...
)
```

Rules:

- Keep each domain to roughly a dozen fields; split a new domain instead of
  piling onto an existing one.
- Every domain ships its own `XxxStringsPatch` / `isEmpty` / `merge`; the
  top-level `merge` only forwards per domain.
- New text = add to the right domain + fill **all three builtin packs**
  (en-US / zh-Hans / zh-Hant).
- A facade may keep flat call sites with delegating getters
  (`strings.theme` → `theming.theme`) so domain splits do not churn consumers.

## 4. Parameterized Text

Never concatenate strings inside components. Templates live in the pack with
`{name}` placeholders, expanded at read time:

```kotlin
// pack: selectedCountFormat = "已选择 {count} 项"
Text(I18n.strings.field.selectedCountFormat.formatArgs("count" to values.size))
```

## 5. Outside Composition

Default parameter expressions on `@Composable` functions can read
`I18n.strings` — they evaluate in composition scope. Two cases genuinely
cannot:

1. **Imperative controllers** (`ActionSheet.showList(...)`): take
   `String? = null` parameters and fall back to `?: I18n.strings.common.cancel`
   inside the `@Composable` host, so resolution still follows the current language.
2. **Plain-class logic** (`FormFieldState.validate()`): inject text at
   construction; direct construction falls back to `StringPacks.English` (the
   library's fallback language). Never write literals. Provide `rememberXxx`
   factories that inject by current language.

The CI guard `scripts/ci/check_i18n_default_text.sh` fails on any Chinese
literal in library source outside i18n packs; the baseline is zero.

## 6. Naming Convention (mandatory)

| Role | Name |
| --- | --- |
| Data model | `XxxStrings` (data class, all fields non-null) |
| Override model | `XxxStringsPatch` (data class, all fields nullable) |
| Builtin pack set | `XxxStringPacks` (object: `English` / `ChineseSimplified` / … + `builtIn: Map<String, XxxStrings>`) |
| Single-language constant | `XxxStringsEnUs` / `XxxStringsZhHans` / `XxxStringsZhHant` |
| CompositionLocal | `LocalXxxStrings` (`staticCompositionLocalOf { XxxStringPacks.English }`) |
| Provider | `XxxI18nProvider(overrides, content)` |
| Accessor | `object XxxI18n { val strings: XxxStrings @Composable get }` |

Consistent naming across libraries lets consumers find the integration point
at a glance.

## 7. Performance (mandatory)

- Do: cache with `remember(tag, fallback, overrides)`; return the receiver
  from `merge(patch)` when the patch is null/empty (zero allocation); read
  `XxxI18n.strings` in O(1) via CompositionLocal.
- Don't: call `resolveLanguagePack` / `normalizeLanguageTag` per
  recomposition; don't move string resolution into `LaunchedEffect` or other
  side effects — it is pure computation.

## 8. Anti-patterns

| Wrong | Right |
| --- | --- |
| A second `LocalLanguageTag` | Read `com.gearui.i18n.LocalLanguageTag` |
| Nesting `I18nRoot(...)` under `App` | `App(languageTag = ...)` already mounts it |
| Provider takes a `languageTag` parameter | Provider takes only `overrides`; language comes from the Local |
| `Map<String, String>` with string keys | Typed data class + accessor |
| Strings inside `MutableState` | `staticCompositionLocalOf` + `remember` |

## 9. Compatibility

- Deleting or renaming strings fields is an API breaking change, blocked by
  `binary-compatibility-validator`.
- Adding strings fields is source breaking (constructor arity changes); all
  builtin packs must be updated in the same change.
- The runtime constraints behind this design are part of the engineering
  rules in [ARCHITECTURE.md](./ARCHITECTURE.md) (single App root, runtime
  ownership).
