# GearUI Kit 1.1 设计：AI 内容块与手机端新组件

状态：草案（本地审阅，不提交）　版本：1.1.0-beta1　平台：仅手机端（iOS / Android；Web 只保证不坏）

## 0. 目标与边界

1. 新增两类组件：
   - **AI 内容块**：可以放在任何消息里使用的通用内容块，不包含聊天列表、气泡和输入框，这些已由 privchat-ui 实现。
   - **手机端新交互**：参照 M3 Expressive 和 iOS 26。
2. 先抽出通用能力，再在其上实现组件；已有组件也改用这些能力，减少重复实现。
3. 性能与 UI 效果按 §4、§5 的规则执行，规则写进组件规范，由检查脚本强制。
4. 不破坏 1.0：公开 API 只能新增。`Strings` 已冻结，新文案放进新的文案域（§3）。

不做：聊天列表、气泡、输入框（privchat-ui 已有）；桌面端组件；Liquid Glass 融合效果（受 Kuikly 渲染器限制）。

## 2. 抽取的通用能力

| 能力 | 来源（现状） | 复用方 |
|---|---|---|
| **Disclosure**：标题行，箭头旋转，「已展开/已收起」读屏状态，按压反馈；正文用弹簧动画展开，收起时**不组合** | `Collapse` 内部的 `CollapsePanelItem`、`CollapseContent`（私有） | Collapse（改用它，行为不变）、Reasoning、ToolCallCard、AgentTrace（完成后折叠成摘要）、CodeBlock（「展开全部」） |
| **ActivityStatus**：`Pending / Running / Succeeded / Failed / Cancelled`；**StatusGlyph**：等待是空心圆，运行中是转圈，成功是对勾，失败是叉，取消是横线，用语义色 | 新增；Steps 的 `StepStatus` 是 1.0 冻结的公开类型，不改它 | AgentTrace、ToolCallCard、Reasoning（思考中） |
| **CopyAction**：复制按钮，点击后 2 秒内显示「已复制」，读屏会播报 | `Snippet` 里的复制按钮（无反馈） | CodeBlock；Snippet 改用它（公开 API 不变） |
| **ConnectedShapes**：按首/中/尾/单个算圆角 | `Segmented` 内部 | ButtonGroup、SplitButton |
| **ChipSurface**：胶囊形可点项，至少 44 高，选中/禁用态 | 新增 | SuggestionChips；之后可给 Tag 的可点版本用 |
| **codeTextStyle**：等宽字体，行高固定，保证行号对齐 | `Code`/`Snippet` 各写一遍 `bodySmall.copy(fontFamily = monospace)` | Code、Snippet、CodeBlock、ToolCallCard 的参数区 |

## 3. 文案（不碰冻结的 `Strings`）

- 新增 `ActivityStrings`（状态词、思考、工具调用、步骤摘要）和 `ActionStrings`（复制/已复制、展开/收起、更多操作、打开/关闭菜单）。各带 en-US / zh-Hans / zh-Hant 三份，按 `LocalLanguageTag` 解析，回退链与 `I18nProvider` 相同。
- 应用可覆盖：通过 `ActivityStringsPatch` / `ActionStringsPatch` 加上新的 Provider（I18N.md §2 的「上层库」模式），不改 `App` 的签名。
- 组件里只用 `I18n.activity.*` / `I18n.actions.*` 读取，不写死任何文案。
- 规则写进 I18N.md：**1.0 之后新增的文案一律进新的文案域，不改 `Strings`**。

## 4. 性能规则（写进 COMPONENT_SPEC，新组件强制）

1. **收起的内容不组合**：Disclosure 正文收起时不在组合树里。长推理、长参数在收起状态下不占布局和测量成本。
2. **长文本用一个文本节点**：不按行拆成多个节点。CodeBlock 只用两个节点（行号列和代码列），代码不换行、横向滚动，所以行号与代码逐行对齐，不需要逐行测量。
3. **超长内容默认截断**：CodeBlock 超过 `collapsedLines`（默认 12 行）就截断并提供「展开全部」，避免几百行代码一次布局。
4. **同时只跑一个动画**：AgentTrace 只有「运行中」那一步转圈；完成后折叠成一行摘要，不再保留每一步的动画。
5. **流式内容可以增量更新**：组件接受不断变长的 `String`，不在组合里做解析。key 用稳定 id，不用下标。
6. **公开模型用普通 `class`，不用 `data class`**：避免 `copy`/`componentN` 成为 ABI 的一部分；日后加字段时加构造重载，不会破坏二进制兼容。这是这次 TimelineItem/SwipeBackConfig 事故的教训。
7. **只读语义色和主题 token**：沿用现有护栏（颜色、圆角、间距、字号、边框不写死）。

## 5. UI 规则

- 内容块统一用卡片样式：`colors.card` 背景、`Theme.shapes.md` 圆角、`BorderWidth.hairline` 的 `colors.border` 描边、内边距 `Spacing.md`，放在气泡里或页面上都协调。
- 状态色：运行中是 primary，成功是 success，失败是 destructive，等待和取消是 mutedForeground。暗色主题自动跟随。
- 所有可点处至少 44×44；Disclosure 标题整行可点。
- 动效沿用 accordion 的弹簧 token；`Theme.motion.normal == 0`（用户关闭动效）时一律不做动画。
- 读屏：标题读成「名称，状态」；折叠项报「已展开/已收起」；复制后报「已复制」；FabMenu 打开时进入模态层（BEHAVIOR_CONTRACT §6）。

## 6. 组件 API

```kotlin
// 代码块：语言标签、行号、复制、超长截断、diff 行着色
CodeBlock(
    code: String,
    modifier: Modifier = Modifier,
    language: String? = null,               // 显示在标题行
    showLineNumbers: Boolean = true,
    collapsedLines: Int = 12,               // 超过就截断；0 = 不截断
    diff: Boolean = false,                  // 以 + / - 开头的行着色
    onCopy: ((String) -> Unit)? = null,     // 宿主负责写剪贴板；为空则不显示复制按钮
)

// 思考过程：思考中显示动画并展开，完成后自动收起成「已思考 N 秒」
Reasoning(
    text: String,
    thinking: Boolean,
    modifier: Modifier = Modifier,
    durationSeconds: Int? = null,
    expanded: Boolean? = null,              // null = 自动（思考中展开，完成后收起）
    onExpandedChange: ((Boolean) -> Unit)? = null,
)

// Agent 执行步骤
class AgentStep(val id: String, val title: String, val status: ActivityStatus,
                val description: String? = null, val detail: (@Composable () -> Unit)? = null)
AgentTrace(
    steps: List<AgentStep>,
    modifier: Modifier = Modifier,
    title: String? = null,
    collapseWhenDone: Boolean = true,       // 全部结束后折叠成「N 个步骤」摘要
)

// 一次工具调用
ToolCallCard(
    name: String,
    status: ActivityStatus,
    modifier: Modifier = Modifier,
    input: String? = null,                  // 参数（常为 JSON），等宽显示
    output: String? = null,
    error: String? = null,
    expanded: Boolean = false, onExpandedChange: ((Boolean) -> Unit)? = null,
)

// 推荐问题 / 快捷回复
class Suggestion(val id: String, val label: String, val icon: IconSource? = null)
SuggestionChips(
    suggestions: List<Suggestion>,
    onSelect: (Suggestion) -> Unit,
    modifier: Modifier = Modifier,
    wrap: Boolean = false,                  // false = 单行横滑，true = 自动换行
    enabled: Boolean = true,
)

// 相连按钮组与分体按钮
ButtonGroup(modifier, theme, type, size) { item(label, icon, onClick, disabled) ... }
SplitButton(text, onClick, menuItems: List<SplitButtonItem>, modifier, theme, type, size, disabled)
        // 右侧「更多」打开 ActionSheet（手机端惯例），读屏名称取自 ActionStrings.moreOptions

// 浮动按钮菜单
class FabMenuItem(val label: String, val icon: IconSource, val onClick: () -> Unit)
FabMenu(icon: IconSource, items: List<FabMenuItem>, modifier, expanded, onExpandedChange)
        // 展开时有遮罩、项从下往上弹出；走浮层运行时，返回键关闭，读屏限定在菜单内
```

BottomNavBar 增强（搜索标签、滚动收起、附件位）单独出设计：要先读现有 API，用重载做到兼容。

## 10. 实施记录与修正（第一批，4cd66499）

- Kuikly 没有 `horizontalScroll`：横向滚动只能用单项 `LazyRow`（与 Snippet 相同），§4.2、§7 的说法作废。
- CodeBlock 不换行的实现：`softWrap = false` 在 Kuikly Android 上会被当作「只显示一行」，Web 上则把空格合并、并按有限宽度测量。
  最终做法是**按等宽字符估算最长一行的宽度并直接设给代码文本**（ASCII 0.62em、全角 1.05em，宁宽勿窄）；Web 另外按「行数 × 行高」固定高度（`measuresTextAtBoundedWidth`）。
- Collapse 的标题是可组合内容、没有文本，无法安全地加「已展开/已收起」读屏状态（`controlSemantics` 会清掉子节点），所以只改结构、读屏不变；新组件都带文本标签，有状态播报。
- Snippet 的复制是带文字的按钮（`copyLabel` 必填，属于 1.0 API），不改成图标；只统一了等宽字体。
- 三端实测：Web（Chromium、WebKit）、iOS 18.2 模拟器明暗两套、Android 真机（小米 12 Pro）。

## 11. 第三、四步记录

- BottomNavBar（35c96c4c）：新增重载带 `accessory`、`trailingAction`；`rememberHideOnScroll` 由纯函数 `barVisibility` 决定，单测覆盖；三端验证收起与重现。
- Haptics + IndexBar 合并（083b45aa / privchat-ui 079834a）：Kit 新增 `Haptics`（iOS 自带；Android 宿主注册 `AndroidHapticFeedback` 并声明 VIBRATE，运行时先查权限）。IndexBar 改为单一手势循环（`requireUnconsumed = false`）、按住字母实心圆、每换一个字母震一次、少于 2 个字母不显示。真机 `dumpsys vibrator_manager` 记录到每个字母一次 TICK。privchat-ui 删除自带 IndexBar，HapticBridge 注册时同时注册 Kit 触感。
- 未做：privchat-ui 的 iOS 编译（Rust FFI 需要 x86_64-apple-ios 工具链，环境问题，与本改动无关）。
